OpenShift Virtualization observability, reference architecture

A virtual machine's metrics, logs and network flows land in the same open, label-indexed stores as every pod and node on the cluster. That is what lets you join them with PromQL, walk from an alert to the VM to its pod to its logs in one graph, and drive the same automation you already use for containers.

5. Decisions and trade-offs

DecisionWhyWhat you give up
One Prometheus for everything instead of a VM monitoring productVM series join pod and node series on shared labels; one query language; one alert pipelineYou size and run the TSDB. At roughly 60 series per VM, 8,000 VMs is about 480,000 series; plan Thanos and retention
Two LokiStacks (logs, netflows)Different tenants and retention; NetObserv expects its ownTwo stores to size. Loki logging defaults to 30 days; forward externally for longer
Korrel8r rules instead of hand-built dashboardsThe walk works for any VM the day it is created; no per-VM dashboard to maintainThe walk is only as good as the rule set in the shipped image; check it
GA COO 1.5.2 (korrel8r 0.11.1)Supported; VMI to pod to logs, metrics and flows works from the VMI pageNo Alert to VMI hop and no VmiToLogs rule until a newer image ships; in this build Focus is disabled on the VM, VMI and pod pages, so you type the query into the panel's editor
Runtime sysctl for schedstats, not a MachineConfigNo reboot on a shared cluster; vCPU wait and delay series appear at onceReverts on reboot. Use the MachineConfig for a permanent install
MinIO in-cluster for S3Fastest way to give LokiStack object storage in a labNot a production object store. Use ODF or an external S3
Guest agent in every VM imageFilesystem, load and IP data; the same dependency VMware Tools hasPanels are blank without it and do not say why

6. Where VMware still wins, said plainly

Capacity planning with What-If modelling, predictive DRS acting on forecast load, built-in cost and chargeback, and multi-year native retention are turnkey in Aria Operations and are not in this architecture. ACM right-sizing (GA in 2.16) is narrower. Say this before anyone asks; it buys credibility for the openness argument.
